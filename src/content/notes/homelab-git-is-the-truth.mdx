## Sixteen guests sit behind one gateway

One Proxmox VE host. Fourteen LXC containers and two VMs. Only two hostnames face the internet; everything else is reachable over the VPN.

<LabTopology />

## Declared, then imported

The hypervisor layer is OpenTofu, through the `bpg/proxmox` provider. Fourteen of the sixteen guests are resources; the dev box and the observability box are not yet. I did not build the lab from the declarations; the lab existed first, so the first job was importing the live resources into state and converging on zero drift. It has not got there yet.

## The nightly job reports drift and commits what changed

A scheduled pipeline runs every night:

- **sync-live** (schedule only): SSH into the host and the gateway, pull the live compose files and configs, and commit whatever changed. The commit is the diff between what git said and what was running. Most nights it is empty. When it is not, it is something I changed on the box and did not write down.
- **tofu-plan**: run `plan` against the live host and report any difference.

The plan job still carries `allow_failure`, with a comment admitting why: the state has not fully absorbed resources created under an earlier provider, so until that one-time import is clean the job reports drift rather than blocking the pipeline. A drift alarm that fires on every run is not an alarm. Making it blocking is the next item, and this paragraph is here so I cannot forget.

## The sync once committed a live credential

A compose stack's `.env` had real values in it, the job pulled it faithfully, and the repo had a database password in history. The fix was three commits. The last added a redaction pass that runs on every synced file before the commit. The sync is now allowed to be faithful because the redactor is in front of it.

## Paging without noise

A health check runs every five minutes. Silent means healthy; it never prints a "healthy" line, because that would page me every five minutes.

<PagingFigure />

Three rules shaped it, each dated in the script's header with the reason it was added:

- **Confirmation gate.** A condition must fail two consecutive runs before it can page.
- **Change-gated alerts.** An alert is emitted only when it is new. While it persists, it re-notifies after a cooldown, six hours for service checks and twelve for the infrastructure watchdog. When it clears, it clears silently.
- **A check that cannot run is itself an alert.** The watchdog that reads TLS expiry, backup freshness and off-site copy freshness treats "could not reach the host to check" as a finding. An unverifiable result is a silent failure wearing a green badge.

## Backups, both kinds

Proxmox Backup Server takes every guest nightly with a kept-copies schedule. Then restic copies the datastore off the host, to a different machine, on its own nightly timer. There is a written recovery playbook next to the restic password. The point of the second copy is that the first lives on the thing that would fail.

## A coding agent did most of the typing

One container runs Hermes, an open-source agent from Nous Research. The HCL, the pipeline and the scripts were written by the agent under my direction, and I made the design calls and reviewed what landed. The agent is an operator, not a place code goes to hide.

## It is not high availability

One host, one power supply, one disk for the photo library. A dead host is a restore from PBS onto new hardware. The declarations cover the hypervisor and the compose stacks; what is inside each container's filesystem is the backup's problem, not git's.
